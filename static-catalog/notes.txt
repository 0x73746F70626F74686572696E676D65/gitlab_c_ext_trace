Scope and output

Additive saved-row review columns are in review-metadata/README.md and
review-metadata/rows.{csv,jsonl}. They record argument-origin evidence limits,
existing call depth, missing nested formal identity, and unassessed local checks.
This companion leaves the original inventory and historical validation intact.
Full registration source identity and binding-status completeness are recorded
separately in registration-provenance/README.md, with 3,655 registration rows
and an explicit unresolved registration-evidence ledger.

entry-argument-sites.csv is the requested call-argument table. Its JSONL
companion contains the same rows, with argument_labels, slot_labels and
visible_parameters represented as arrays rather than JSON text in CSV cells.
summary.json and summary.txt give roots, rows and unresolved hops.

The starting analysis-repository work SHA is recorded in summary.json. The
catalog's GitLab SHA and lockfile remain unchanged. Only the 70 locked package
variants needed for the 69 extension gems in files-scanned.csv were restored.
Package hashes were checked against fetch-manifest.json and the lockfile, and
all 5,773 recorded source-file hashes were verified. The source cache is outside

not cloned because Gemfile.lock was already present. Only archive readers,
parsers and analysis tooling ran; no Ruby, extension, gemspec, extconf.rb, build,
application, endpoint or source snippet was executed.

The former unchanged/unbound-value catalog is preserved as

Roots and indices

All catalog registrations of rb_define_method, rb_define_singleton_method,
rb_define_module_function, rb_define_private_method, rb_define_protected_method
and rb_define_alloc_func are counted as roots, including unresolved bindings.
argument-inventory-roots.jsonl records their current binding status and names.
Ruby receiver expressions are retained without claiming a resolved class.

argument_index is zero based and identifies a Ruby positional argument, rather
than an operand of the call at the site. For fixed arity, C parameter zero is
self; C parameter i+1 is Ruby argument i. Self and an allocator's klass argument
do not seed a Ruby positional index. Zero-argument and allocator roots are still
traversed and counted. Arity -1 argv[i], arity -2 rb_ary_entry(args,i), and the
fixed outputs of literal rb_scan_args/rb_scan_args_kw formats identify positional
arguments. Positional extraction into a named local is treated as a parameter
binding. Metadata argc, the unsliced argument vector, dynamic positions, rest,
keyword and block outputs do not identify one positional argument. Output
addresses of rb_scan_args do not use the parameters that that call extracts.

c_function is the registered root; site_function is the enclosing function at
the call/store. parameter_name names the root formal or positional-extraction
binding. slot_argument_index is the zero-based C call operand, not the Ruby
argument index. An indexed assignment has slot_argument_index -1, because its
index is an assignment subexpression rather than a C call operand.

Traversal and visible parameters

The analysis inventories syntactic occurrences of mapped parameter names. A
parameter anywhere in a call's operands or either side of an indexed store can
include that site; it need not appear in the selected slot. For example,
memcpy(dst,source,16) gets a length/literal row for parameter source, and
printf("%s",value) gets a format/literal row for parameter value. A sizeof
operand retains its sizeof label even when its syntax mentions a parameter.

Direct intra-extension helper arguments map these occurrences to the root's
parameter positions. Helpers are traversed to arbitrary acyclic depth, including
helpers with no mapped inputs so that their unresolved boundaries are recorded.
One shortest context for a given function/input binding is retained per root.
hop_count is zero at the root, one in a directly called helper, and so forth.
File-local definitions take precedence; other helpers must have an unambiguous
visible definition in the same native build group. Different extension build
groups inside a gem are not joined merely because their functions share a name.

This is an argument-position inventory, not a value-provenance analysis. A
formal remains a formal if its value is reassigned. General local aliases,
helper return values, external return values, heap/field aliases and global
state do not create mapped parameters. Actual arguments containing nested calls
do not transfer origins to helper formals through those calls' return values;
in particular, unexpanded macros stop such a transfer. These would require a different analysis.
The named local bindings from Ruby positional extraction are the explicit
exception. Field/base expressions are inspected for visible parameter syntax,
without assuming the field's value equals the parameter's value. Conditions,
dead code, loops and parsed preprocessor branches are inventoried as syntax;
their runtime admission is not solved.

Function pointers, member dispatch and all unexpanded macro hops stop traversal
and are recorded in unresolved-hops.csv.gz. The body of a macro is never expanded.
An outer call such as memcpy(dst,RSTRING_PTR(str),len) may still visibly name str
and receive a row without inferring the result or behavior of RSTRING_PTR. Known
allocation/copy macro signatures permit labels at the literal macro invocation,
and their implementation hop is still recorded as unresolved. Registration
function macros are not expanded into roots. Cast wrappers do not add hops or
sites. free-family calls are skipped. libc implementations are never followed.
Other missing external implementations, ambiguous definitions, recursion,
unknown format signatures, unsupported positional extraction and functions with
parser recovery are additional unresolved boundaries. A function with parser
recovery is not traversed to justify rows.

Labels and slots

Each call operand is classified in argument_labels. The selected slot operands
are classified in slot_labels; argument_label is the representative slot label.
Categories are param(name,index), sizeof, literal, local, and other. A param
expression visibly contains a mapped formal or positional-extraction binding,
including nested arithmetic, casts or call syntax. sizeof has precedence for a
whole sizeof expression. Literal means a C numeric/character/string/bool/null
literal. Local means an expression containing an unmapped formal or declared
local. Other covers remaining expressions, constants whose definitions were not
expanded and type operands. No runtime value or magnitude is assigned to a label.

Length slots: memcpy/memmove/mempcpy/bcopy/strncpy/strncat and corresponding
selected wide-character calls use operand 2. MEMCPY/MEMMOVE and RB_ equivalents
use operand 3 (the element count). Unbounded strcpy/strcat/wcscpy/wcscat have no
explicit length operand and therefore cannot produce a length-slot row.
Bounded snprintf/vsnprintf/swprintf/vswprintf also have length operand 1.

Size slots: malloc/alloca and Ruby xmalloc equivalents use operand 0;
calloc/xcalloc/xmalloc2 equivalents have both factor operands 0 and 1;
realloc/xrealloc use operand 1; xrealloc2 equivalents have factors 1 and 2.
ALLOC_N/ZALLOC_N/ALLOCA_N use count operand 1; ALLOCV_N/REALLOC_N use count operand
2; ALLOCV uses byte operand 1. RB_ equivalents use the same positions. ALLOC
and ZALLOC have an implicit sizeof(type) size, labelled without expansion.
Element counts are recorded as counts rather than claiming evaluated byte sizes.
No arithmetic, narrowing, overflow, guard, or later-copy predicate is required.

Format slots use the recognized printf/scanf standard signatures and Ruby
equivalents in catalog.py's RUBY_FORMAT/format_index. They describe the format
operand, rather than each variadic value. Literal formats remain classified.
An unknown signature is unresolved rather than assigned a guessed operand.
Index slots are subscript stores and *(p+i) stores, including compound/update
stores. The selected index is the outermost subscript, or the right operand of
the recognized p+i form. No adjacent-line comparison or guard filter is applied.

Deduplication

The exact requested key is gem + ruby_method_name + argument_index + numeric
site_line. It intentionally does not add a receiver, source filename or slot.
When several candidates share that key, the representative uses the shortest
helper path, then favors a slot mentioning that Ruby argument, followed by
stable source/operand ordering. argument-inventory-dedup-collisions.jsonl
preserves all distinct alternative slots, receivers and physical sites suppressed
by this key. Thus the table has one representative per requested pair and the
companion retains the other evidence. slot_labels also retains every selected
slot at the representative call, such as both a snprintf format and bound.

Unresolved-hop counts are per root + site file + site line + target + reason;
they are not argument-specific. This differs from the former provenance ledger.
argument_indices lists parameters visibly present at each unresolved site and
can be empty. Outside-extension boundaries and parser/registration gaps are
included in the total, not just macro and pointer boundaries. Source/path
associations and these counts do not establish runtime reachability or behavior.

Source coverage limits

The catalog's 23 skipped records (including nested native archives), unparsed
lexical candidates, generated-source omissions and parser diagnostics remain.
No new gem version, external library implementation or nested source archive was
added. files-scanned.csv supplies the exact extension-associated source roots,
including the originally catalogued bundled C/C++ source. Files with identical
bytes at the same gem/version/path retain the catalog's platform deduplication.
These are source-associated files, not a claim about which ones a build links.

Reproduction and validation

Install scripts/requirements.txt in the Python analysis environment, then run:
  python scripts/restore_inventory_sources.py
  python scripts/call_argument_inventory.py
  python scripts/validate_call_argument_inventory.py

Run from static-catalog or pass --out to call_argument_inventory.py. The source
restore script defaults to the source directories in fetch-manifest.json and
fetches only a missing locked variant required by files-scanned.csv. It evaluates
no Ruby/build metadata. The original entry_catalog.py/finish_delivery.py implement
the preserved earlier objective and should not regenerate this new table.

validation.json records inert-snippet checks, source-reference/digest checks,
CSV/JSONL agreement, slot/count integrity and exact-key deduplication. SHA256SUMS
covers the updated delivery. These checks verify the recorded syntax and data
integrity; no target code or runtime extension tests are executed.
