# GitLab anonymous HTTP and GraphQL inventory

Use `http_unauthenticated.json` for HTTP route registrations and `graphql_unauthenticated.json` for GraphQL schema fields. `unauthenticated.json` combines both. These are source-supported classifications at GitLab commit `d75e5afaa21d45bc04139d4a538ea5954be1ef4f`; they are not a runtime-verified allowlist. Authentication resolution is incomplete and `metadata.complete` is deliberately false.

`unconditional.json` selects records without a detected mandatory identity gate. `conditional_anonymous.json` selects records that admit anonymous access under recorded resource, setting, feature, network or routing conditions. Both may require a valid request and deployment configuration. `authenticated.json` contains detected identity/credential requirements. `unknown.json` contains unresolved cases; it must not be treated as private or public. A login page and a successful password submission are distinct records. Redirects, empty identity responses, error-only handlers and WebSocket handshakes have explicit `response_kind` values where recognized. Error-only records are excluded from the combined public lists.

Each entry has the source revision, edition, method(s), route template, controller/action or GraphQL field/resolver, registration location, conditions, evidence IDs and gap IDs. `evidence.json` resolves those IDs and the inherited callback pipelines. Main-listener paths require the configured `relative_url_root` prefix; dedicated health-listener paths belong to a different listener. `ANY`/`ALL` represent declared wildcard verbs; `UNKNOWN` means the reused snapshot or proxy registration did not provide a verb. CE and EE are independent profiles, and organization-prefixed registrations are separate records.

GraphQL fields share `/api/graphql`; their counts are not HTTP route counts. `schema_path` is a shortest source-derived witness through return types, with cycles collapsed. `... on Type` denotes an inline-fragment step. Conventional `.connection_type`/`.edge_type` traversals use `nodes`/`node` steps. All members generated by the GraphQL framework, connection customizations, runtime union/interface resolution, introspection and field extensions are not fully expanded. Subscription transport authorization remains unknown; accepting a WebSocket connection does not establish admission to a subscription.

## Coverage and method

`entrypoints.json` is the whole reconstructed inventory. `coverage.json` includes every template in GitLab's existing 5,058-template EE routing snapshot, whether resolved to source registrations or retained as an unknown snapshot record. That snapshot was generated by GitLab's CI/test configuration and is reused without booting GitLab. It does not contain HTTP verbs or handlers. Snapshot matching normalizes optional format suffixes, trailing slashes and the known API v4 version token; it does not imply that arbitrary API versions work.

The generator reuses the prior 23,370-file Ruby/Rack source index and entrypoint discovery data. It expands all 76 CE/EE Rails route files, REST resources, concerns, literal loops, draw chains, scopes, mounted Grape APIs, GraphQL root registrations and explicit result types, Devise/OAuth route macros, Rack maps, health middleware/listeners, ActionCable and Workhorse dispatch registrations. The former public-method/resolver candidates that lack a reconstructed registration are recorded in coverage. No gem API inventory or memory-operation analysis is performed. Locked routing-framework gem archives are downloaded, SHA-256 checked and read as source only; gems and GitLab are never installed or executed.

Authentication review examines inherited `before_action`/`around_action` filters, selector options and skips, route authentication scopes, Grape mount/namespace hooks, explicit authentication/authorization helpers, GraphQL type/field/resolver declarations and mutation denial policy. Direct auth-helper review is capped at six calls. It follows source-resolved inheritance `super` calls and records dynamic dispatch, missing definitions, unresolved permissions, conditional credential gates and cutoffs. Public-resource permissions retain their conditions. Three guest-compatible CE callbacks reuse the existing source review; overrides are reviewed independently.

This is a bounded static classification, not exhaustive program analysis. An ordinary helper or service can contain an undiscovered identity gate; permission outcomes, middleware, configuration, route precedence/shadowing, custom engines, generated fields, runtime type feasibility and Ruby metaprogramming can change reachability. All recorded gaps, parse errors, excluded Ruby/Rack files, unresolved registrations and declarations without schema paths are retained. JavaScript client calls do not create server entrypoints. Implicit HEAD/OPTIONS and static assets/reverse-proxy configuration are not fully enumerated. The JSON intentionally makes no near-perfect or deployed-completeness claim.

## CI use and regeneration

Validate the saved data without booting GitLab:

```sh
python unauthenticated_entrypoints/validate_inventory.py
python -m unittest discover -s unauthenticated_entrypoints -p test_inventory.py
```

Filter by edition and inspect conditions before using records as a CI baseline. Compare stable `id` values and source revision, and review changes to the unknown partition as well as additions to the public partition. `inventory.schema.json` describes the entrypoint JSON documents. `validation.json` records integrity/source checks and pinned-route smoke checks; these are static checks, not request tests.

To reproduce this snapshot with the existing source index:

```sh
python -m pip install -r unauthenticated_entrypoints/requirements.txt
python unauthenticated_entrypoints/fetch_engine_sources.py --source /workspace/gitlab-frontend-source
python unauthenticated_entrypoints/build_inventory.py --source /workspace/gitlab-frontend-source
python unauthenticated_entrypoints/validate_inventory.py --source /workspace/gitlab-frontend-source
```

The local source cache is optional and must be trusted: it is a Python pickle produced in this workspace. A cached index or prior inventory from another revision is rejected. To parse a new clean source checkout, pass `--cache '' --baseline /path/to/empty-directory`; this uses the existing parser without API matching. Route-macro expansions and manually reviewed contracts are version-specific and need review when the framework or GitLab contracts change. External framework sources are obtained by `fetch_engine_sources.py`; `--engine-source` changes their directory. The previous API JSON and previous analysis artifacts are unchanged.
